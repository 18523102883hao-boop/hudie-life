## 4. 建议字段映射与显示规则

以下字段名是开发沟通建议，不是已发现的API或数据库字段。实施前由开发对照真实接口填入映射。

| 显示 | 建议语义 | 必要规则 |
|---|---|---|
| 售价 | selectedSku.salePrice | 正数、币种与精度统一；与下单确认一致 |
| 划线价 | selectedSku.referencePrice + referenceType | 有可解释来源且高于售价才显示；类型决定叫门市价、参考价等 |
| 折扣 | 折扣计算值或后台有效折扣 | 与售价及参考价匹配；不小于0、不显示10折及以上促销标签 |
| 已售 | soldCount + countScope | 0是有效值；商品级与SKU级不得混用或重复累加 |
| 剩余 | availableStock + stockScope | 明确商品库存还是SKU库存；0是售罄；未知值不当0 |
| 结束倒计时 | activity.endAt + serverNow | 依据服务端结束时间计算；刷新页面不得重置 |
| 商品标签 | 当前商品支持的能力 | 免预约、保障、退改等必须有对应规则 |
| 可选补贴 | 真实补贴/优惠资格及计算结果 | 本版未承诺补贴；有真实能力才增加，不照搬享库补贴额 |

如果用户要求展示“原价”，需要先确认这个金额在业务系统中的真实含义；仅有一条划线价截图不足以证明它是历史真实成交原价。

## 5. 状态和长内容

- 缺参考价：保留售价，隐藏划线价和折扣；不补一个虚构原价。
- 已售为0：正常显示0；数据缺失/请求失败不伪装成0。
- 库存为0：显示“已售罄”，购买入口禁用；其他仍有库存套餐可切换。
- 库存未知：显示“库存更新中”或隐藏数字，并在购买前校验；不制造“仅剩”。
- 活动结束：倒计时改为“活动已结束”，购买行为按后台活动状态处理。不可自动重开倒计时，也不可擅自推断仍可按活动价购买。
- 结束时间缺失：不显示倒计时；存在真实限量但没有时间限制时只显示库存。
- 天数三位以上、主价带小数、销量过万或标题很长：允许辅助行换行、模块增高；不覆盖数字、不压缩为10px小字、不裁切金额。
- 未选套餐：按钮先引导选择；缺货套餐不可选，切换后刷新价格、库存和费用包含。
- “已售件/份/张”：按后端真实交易单位统一，不能在首页按订单数、详情按人数而仍叫同一个销量。
- 不把活动结束时间与购买后使用有效期混为一个倒计时；须知中的有效期另列且需要真实规则。

6. 价格和库存下单前服务端复核；倒计时刷新不重置，活动到期自动变更状态。
