# 源码对照与页面映射

所有相对路径均以同目录“源码快照/”为根。行号指本次 ZIP 内快照；开发修改后可能变化。
标记“现有”表示源码中已存在；“提案”表示本次视觉调整，尚未实现。

依据：`pages/product/info.wxml`、`info.js`、`utils/product-price.js`。

| 区域 | 现有来源/动作 | 必须保留 |
| --- | --- | --- |
| 首图 | goods.imgs | 空图与多图条件；多图才有指示点 |

| 标题 | shop_name、title、is_virtual | 门店名与商品标题的层级，虚拟商品分支 |

现有购买状态分支依次涉及 status、start_time、end_time、stock 和 today_sale_num。效果图只显示在售可购买状态；未开售、已结束、已下架、已抢光均需保留。

分享后现有功能：服务端海报、保存海报、一键复制文案及关闭。无文案时逻辑不同。海报由 product/getQrcode 返回，页面改色不代表服务端海报同步改色。本次没有设计新的支付或分享链路。

## 4. 详情页套餐与图文：图 03

图 03 两个画面是同一页面的不同滚动位置，不是新增路由。

- 套餐来自 goods_list，使用 selGoodsSpec 切换。当前切换会替换完整 goods 对象，可能连带更新主图、价格、倒计时、门店及分享信息；不能只画一个选中框而不切数据。
- 套餐价格为 subsidy_price，缺失时为“价格待确认”；market_price>0 才显示套餐划线价。
- 套餐销量 display_sale_num 当前为 sale_num + virtual_sale_num，和首屏口径不同。
- 结构化“费用包含”仅在 package_content_visible 为真时展示；其来源是 extend.package_content.enabled=1 且存在 groups。
- 组内保留 title、rule、dish.name、name_en、qty、price 及 price_strike 等条件信息。没有结构化数据时，不要硬造费用表。
- 商品图文、使用说明仍来自 content 与 rule 富文本，完整呈现，不用效果图节选替换。
- 视频号商品 ID 仅在有值时显示，保留 copyVideoGoodsId；长 ID 自动换行，复制按钮独立占位。
- 商家资质调用 viewLicense；合作入口调用 openPartnerQr。看见入口不能视为已经核验资质。
- 源码没有“套餐内容 / 购买须知 / 商品详情”三项吸顶锚点，也没有展开收起动作。本版没有把竞品这些控件作为已实现功能。
- 图中省略号用于说明长页面节选，不是开发时截断交易说明的设计。

主要锚点：WXML 第 76—100 行套餐和结构化内容，第 102—125 行富文本、ID、资质及合作；JS 第 349 行附近的 selGoodsSpec。

## 7. 普通商品下单：图 06 左

依据：`pages/product/place.wxml`。

保留商品图、标题、单价/划线价、数量加减、total_price、姓名、手机号、备注、完整须知和同意勾选，底部为总价及确定支付/领取。

图中选择：need_playdate 为真；need_idcard 为假；非 is_virtual=2。故显示游玩日期，不显示身份证和上门地址。实际其他商品需要按条件显示，不能按截图永久删除字段。

存在 reward_id 时数量及领取行为与普通购买不同。是否满足勾选、输入及交易条件由原有处理逻辑校验；本版未更改支付实现，也没有证明支付链路已通过测试。不得新增无后台依据的优惠券选择器。

## 8. 订单列表：图 06 右

依据为 `pages/order/index.wxml`，不要误用另一个 `pages/order/list.wxml`。

- 本页源码没有搜索框、卡片内支付/退款按钮，也未启用底部 TabBar；本版保持。
- 图中订单号、日期、状态和金额仅用于展示，不是后台真实订单。
- 无订单、加载中和失败的原有处理仍需保留。
