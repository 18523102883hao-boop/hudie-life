# 视觉尺寸与开发交接

本文件给出开发建议值，尚未写入小程序。效果图有不同缩放与少量生成差异，最终颜色、字号及组件应统一使用本文件约定，不直接量 PNG 像素。

## 1. 品牌与视觉原则

沿用用户提供的橙色几何蝴蝶标志，使用奶油白、品牌橙与深色文字；学习参考产品的信息秩序。品牌图形不要拉伸、改成竞品图形，或加入未经确认的官方认证与平台背书。

现有微信胶囊、系统导航和原生权限提示遵循真实运行环境，不将装饰效果图当作这些控件的可任意修改区域。

## 2. 建议色值

| 用途 | 建议值 | 使用说明 |
| --- | --- | --- |
| Logo / 品牌点缀 | #EF981F | 蝴蝶、装饰、图标点缀 |
| 强操作底色 | #B45609 | 白色按钮文字的深橙底；大面积橙色可使用浅深层次 |
| 强操作文字 | #FFFFFF | 配合深橙底，最终须实测对比度 |
| 奶油底 | #FFF8ED | 标签底、头像底、轻品牌区域 |
| 页面底 | #F6F6F3 | 卡片之间的背景 |
| 卡片 | #FFFFFF | 主内容区域 |
| 主文字 | #24211D | 标题、正文、表单值 |
| 次文字 | #706C66 | 元信息、说明、未选中导航 |
| 分割线 | #E9E5DF | 轻边界 |
| 主价格文字 | #A64F08 | 白底价格与重点数字 |
| 售罄/禁用底 | #E7E3DD | 须配相应状态文字 |

价格条的浅亮橙至深橙层次可以保留视觉提案，但不能用浅橙上的白色小字造成难读；实施时对比度不足就加深文字所在底色，或改为深色文字。最终对比度和真机阅读尚未测试。

## 3. 文字体系

默认系统字体 PingFang SC，回退至系统 sans-serif。中文正文不使用装饰字体。不要为了装下内容无限缩小字体。

| 内容 | 逻辑字号 | 字重 / 行高建议 |
| --- | --- | --- |
| 页面/卡片主标题 | 18px | 600，26px |
| 商品标题 | 16px | 600，24px |
| 正文、字段值 | 14px | 400，22px |
| 按钮 | 16px | 600，22px |
| 标签、辅助信息 | 12px | 400—500，18px |
| 首屏主价格 | 32px | 600—700，38px |
| 卡片价格 | 22—24px | 600，28px |
| 货币符号 | 16px | 与价格基线对齐 |
| 划线价 | 12—13px | 400，完整显示金额 |
| 倒计时数字 | 14px | 600，尽量使用等宽数字 |

长商品标题可在列表最多两行，但详情页、须知、表单错误、完整地址等关键内容应换行或进入完整详情，不能误删。金额大于四位、带两位小数时，布局必须自适应。

## 4. 尺寸与栅格

尺寸以 390px 宽的逻辑画布为基准。小程序通常使用 750rpx：换算 rpx = 逻辑 px × 750 / 390，约 ×1.923。不是把所有图片像素一律乘 2。

| 项目 | 建议逻辑尺寸 |
| --- | --- |
| 页面左右边距 | 16px |
| 卡片之间距离 | 12px |
| 卡片内边距 | 16px |
| 卡片圆角 | 16px |
| 同组内容间距 | 8px / 12px |
| 最小点击区域 | 44 × 44px |
| 主 CTA 高度 | 48px，圆角 24px |
| 次按钮高度 | 44px |
| 表单基础行高 | 至少 56px，错误信息另占行 |
| TabBar 内容区 | 建议 54px，另加底部安全区 |
| 功能线性图标 | 24px，建议统一约 1.8—2px 视觉线宽 |
| 分类图标画布 | 40px，图形约 28—32px |

首页五分类等宽。390px 下扣除两侧 16px 后，每个槽约 71.6px；图标与标签居中，整个槽可点。
上新卡仍每组三项，扣除 16px 左右内边距及两个 10px 间隙后按实际容器计算宽度，不固定死一个 PNG 宽度。

## 5. 商品详情关键组件

### 价格条

390px 下可用宽度约 358px。无佣金时建议最小高 64px；有“自购省 / 分享赚”时自适应至约 86px 或更高。

左侧为价格、折扣和划线价，右侧为立即分享，右侧建议预留 108—116px。金额/折扣容不下时允许在左侧分两行，不能覆盖分享区，也不能剪掉小数位。佣金文本仅在原条件成立时出现。

### 销量、库存与倒计时

本次提案采用两行：第一行已售与剩余，第二行“距结束”与时间，避免同一行四类数据互挤。
倒计时块建议至少 24px 宽、26px 高；天数达到三位时自动加宽，不能假设始终两位。时间单位与数字块分开；结束状态不用负数倒计时。

这些是布局建议，不改变现有数字计算含义。

### 门店、套餐和长内容

门店导航与电话各有至少 44px 点击区。地址自动换行，不能与右侧按钮重叠。
套餐选中同时使用边框、浅底和勾选标记；不要仅依赖颜色。选中后全页数据按原逻辑更新。
费用包含列表根据是否有数量和单价自适应列宽；没有单价则不预留空数字列。
视频号商品 ID 允许换行；复制按钮保持独立点击区。
content、rule 富文本应检查外来固定宽度图片/表格；关键条款全文保留，行高正常，不能被底栏盖住。

### 固定底部

底栏增加 `env(safe-area-inset-bottom)` 对应安全区。页面正文末尾预留“底栏总高度 + 安全区 + 至少 12px”间隔。客服悬浮入口与底栏、键盘、弹层避让，不能压在提交按钮上。

## 6. 需要改动的样式与资源位置

| 位置 | 改造重点 |
| --- | --- |
| utils/theme.wxss | 共用颜色、文字、卡片及操作样式 |
| utils/theme.js | 与 WXSS 同步的主题值 |
| pages/index、product、foodmap、mine、order 对应 WXSS | 页面局部尺寸、间距与状态 |
| WXML 内联样式、绑定颜色、Vant 控件属性 | 排查残留蓝色及固定尺寸 |
| utils/common/tabbar、goods_list | 共享导航、列表价格与标签 |
| 本地蓝色分类与 Tab 图片、地图标记 | 待确认后统一替换素材 |
| price_bg.png | 当前促销价格背景图，需替换或改为可伸缩样式 |
| 商品海报 | 服务端生成，需要另查模板配置，不能只改本地图片 |

仅修改 theme.wxss 不能保证所有页面统一。当前源码还包含硬编码、局部样式、PNG 和 iconfont；逐项核对实际引用再替换。

## 7. 视觉确认后的图标交付要求

本次不把效果图里的图标直接裁切交给开发。确认风格后，应制作清晰的独立资产：

- 分类五项；底部导航三项的默认/选中状态；订单状态；客服、达人、团队、资料、邀请码；地图与门店、导航、电话；复制、分享、关闭、箭头与选中等。
- 原始矢量源文件、透明 PNG 及命名映射。小程序能否直接使用 SVG 须按实际基础库及组件验证，不预设所有场景均可。
- PNG 优先以实际引用槽尺寸输出至少 2 倍清晰度；TabBar 等平台要求按开发环境单独核验。
- 同一图标默认/选中保持相同画布、中心及视觉大小，命名包含功能和状态。
- 不把背景、文字、按钮和图标烘焙成一张图。文字仍用系统文字，动态数字仍用真实字段。

## 8. 实施后的验收清单

以下是后续执行清单，本次尚未完成：

- 320、375、390、430px 等宽度与不同安全区；字体放大；长昵称、长标题、长 ID、大金额、三位天数。
- 首页三项轮播、五分类、无商品、分页、公众号关闭、客服与福利群动作。
- 详情零佣金/有佣金；无划线价、缺价；未开售/结束/售罄；多门店/虚拟商品；有无结构化套餐与富文本。
- 切换套餐后主图、价格、库存、倒计时、分享图和下单项是否同步。
- 地图无定位、拒绝定位、同意定位、无店、加载失败、marker 与抽屉联动、筛选与搜索。
- 我的普通/达人、已绑定/未绑定、额外权限入口、金额显隐、失败重试。
- 下单需日期/身份证/地址、领取分支、数量边界、勾选须知、键盘避让和错误提示。
- 五项订单筛选以及部分核销、退款、取消、空列表等状态。
- 页面截图逐张检查：文字无重叠或裁切、价格完整、操作点击区够大、底栏不盖内容。
- 最后再做接口联调、真机交易与海报验收；导出成功不等于视觉和业务验收通过。
